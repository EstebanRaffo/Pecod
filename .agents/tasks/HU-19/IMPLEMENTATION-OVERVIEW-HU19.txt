    → Evita versionado complejo de JSON schema

2️⃣  Edición vía endpoint PATCH existente (no separado)
    → Profesor edita maxAttempts igual que minScore o título
    → Reutiliza lógica de autorización y validación
    → UX cohesiva (misma pantalla de edición)

3️⃣  Validación doble: Frontend + Backend
    → Frontend: input number con min/max (UX inmediata)
    → Backend: @IsInt @Min(1) @Max(5) (seguridad)
    → Mensajes en español en ambas capas

4️⃣  Reducir límite: Alumno bloqueado si agotó con anterior
    → Consistencia: política más restrictiva gana
    → Si 2 intentos fallidos con limit=3, pero se reduce a 2, queda fuera
    → Previene abusos de edición de límites

5️⃣  Certificado usa máximo vigente
    → "Agotado" = intentos fallidos >= evaluation.maxAttempts
    → Cambiar límite cambia elegibilidad instantáneamente
    → No hay caché de estado previo
